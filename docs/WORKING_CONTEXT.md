# Working context

Last updated: 2026-11-11

Read this after `docs/GUIDELINES.md`. It is a short handoff for facts that are useful when resuming work but do not belong in stable documentation. Verify time-sensitive statements against the code, documentation, and Git status before acting on them.

## Current state

- The commit after the upstream "deboat altair" commit ports generic fixes from games built on Altair, together with the fixes from a review of that port (summarized below).
- Utility layout since the deboat merge: Altair's own utilities live in `src/util/Core`, everything else is an `altair-utils` package installed with `bash require-dependency.sh`, and `src/util/Effects` is installed and committed because `SettingsUI` requires `ClickRipple`. See [Utility Dependencies](dependencies/README.md).
- The FOV pulse removed from `src/util/CameraNudge` (`PulseFov` / `ReleaseFovPulse`) is in the published `altair-utils` Camera package since 2026-11-10 (`85c6f89`), so `bash require-dependency.sh Camera` installs it.
- Before testing in Studio, run `bash update.sh` (it reapplies `patches/`), then restart `bash serve.sh` and reconnect Studio, so that a fresh Rojo session also removes an old `ReplicatedStorage.client.exec` copy of the entry scripts. `wally.toml` pins `bridgenet2-fork` (`=1.1.5`) and `cmdr` (`=1.12.0`) to the versions the `patches/` files target; regenerate a patch before raising its pin.

## Recent changes

- Guidelines: `docs/GUIDELINES.md` is reorganized into ten numbered sections and states the loader order, module types, placement, bridge, data, receipt and loading rules as the code implements them, with a tested `luau-lsp analyze` command. `docs/README_SIGNALS_AND_BRIDGES.md` is outdated, and the guidelines say so. See [Guidelines](GUIDELINES.md).
- Tools: `rokit.toml` pins rojo 7.7.1, selene 0.32.0, StyLua 2.6.0 (tool name `stylua`, which `generate-reflex-types.sh` now calls), wally-package-types 1.7.0 and luau-lsp 1.70.1; Rokit's luau-lsp replaces the committed `luau-lsp.exe` 1.52.1 and also runs on macOS and Linux. `selene.toml` raises mixed tables, ignored results that must be used and the two UDim2 lints to errors (duplicate keys and reverse loops are errors by default) and keeps `global_usage = "allow"` (the Reflex profiles declare global `CreateProducer` functions), `stylua.toml` spells out its settings, `.styluaignore` skips Freecam and the Wally packages, `.luaurc` sets nonstrict mode and `.gitattributes` checks out LF on every platform. With these versions selene reports nothing in `src/`, StyLua 2.6.0 reformatted one type in `MonetizationConfig.luau`, and luau-lsp 1.70.1 passes every file in `src/` once `SettingsUI` watches `Enabled` through its `any`-typed `effect` (the newer definitions check the property name that `GetPropertyChangedSignal` gets); the gaps of the 1.52.1 definitions (`Player.IsFriendsWithAsync`, `Enum.ExperienceEventStatus`, four `Enum.KeyCode` items in Freecam) are gone.
- Documentation layout: `AGENTS.md` is the entry point that AI agents load (start steps, hard rules, project map, scripts, checks before finishing), the full rules are `docs/GUIDELINES.md` and this handoff is `docs/WORKING_CONTEXT.md`; there are no tool-specific rule folders or files. Agents read the whole output and exit code of every script they run and report its results (see [Script output](GUIDELINES.md#script-output)).
- Loading: the Initializer sets the `LocalPlayer` attribute `LoadingReleased` as the last release step on every path, right before `PlayerReady`; code that waits for the loading screen waits for it instead of looking for `LoadingUI`. See [Preload](README_PRELOAD.md).
- Security: the server's bridge remotes confirm only bridges the server itself created and never create one for a client (with request limits); Cmdr's `BeforeRun` is an allow-list, so without the role only the `Help` group runs; developer product receipts are deduplicated through `monetization.purchaseIds` and the profile MetaTag `purchaseIds`, and acknowledged only once a DataStore save holds the grant; purchase prompts have server and client cooldowns; the client-written `BreakBarrierBaseNumber` attribute is gone; redeem input and `FriendBoost` payloads are validated. Since 2026-11-11 a client profile action must also be one of the producer's actions (`getActions()`), never a producer method such as `resetState`, and a game pass bought in the experience is granted once `UserOwnsGamePassAsync` confirms it (checked again for about a minute because of its cache; Studio test purchases need no confirmation).
- The server bootstrap connects `PlayerAdded`/`PlayerRemoving` before `Init` and gives each controller `PlayerAdded` once per player.
- Cmdr: `ServerCmdr` registers hooks first and then sets the `CmdrClient` attribute `Registered` (its module count); `ClientCmdr` loads Cmdr's client in its own thread only once it has received that many modules. Cmdr's client registers only what `CmdrClient` holds when it is required, so a client that required it before the server's `Init` had no commands until it rejoined. `ServerCmdr` also requires Cmdr's `var`/`var=` server parts when it loads, so their DataStore check is over before a waiting client's first `var` (an earlier `var` never got an answer). Play-tested in Studio on 2026-11-03, including late registrations; the old code reproduced the bug. See [Server Modules](README_SERVER_MODULES.md) and [Client Modules](README_CLIENT_MODULES.md).
- New `GameConfig` switches, all off by default: `game.antiKick.enabled`, `game.friendBoostEnabled`, `game.vipChatTag` and `ui.windowFieldOfView` (`OpenGui` no longer touches the camera unless it is on). `core.resetButtonDisabled = true` now disables the reset button and `false` leaves it alone. `game.eventPromptId` is gone and `ui.strokeAdjuster.excludedGuiNames` is empty.
- `src/exec/Freecam.client.luau` is vendored and exempt from the style rules (see [Client Modules](README_CLIENT_MODULES.md)). `FocusController`'s HUD and camera also wait while `FreecamEnabled` is `true`.

## Games that take this version

- Tools: run `bash update.sh` (it runs `rokit install`) and `rojo plugin install`, so that the Studio plugin matches Rojo 7.7.1, and download the luau-lsp 1.70.1 definitions ([Running luau-lsp](GUIDELINES.md#running-luau-lsp)). A checkout made before the new `.gitattributes` keeps CRLF files until Git writes them again; `stylua <path>` rewrites one with LF without changing its content in Git.
- Set `core.resetButtonDisabled = false` in games where `true` kept the reset button, and turn on the new switches the game relies on.
- `MonetizationButton` lost the implicit `Shop` ancestor rule, the default `ONLY` price prefix and the StudPattern greying: set `KeepVisibleWhenOwned` and `PricePrefix` where needed; owned-offer buttons now hide only with `HideOnComplete` (otherwise they show the greyed `OWNED` state, as owned game-pass buttons now do too), so add `HideOnComplete` to offer buttons that should disappear once owned.
- Double `FloatSpeed` values: `FloatAnimation` no longer renders twice per frame.
- `RaycastActions` no longer listens to `LockBridge` or plays `SoundService.LocalEffects.LaserGate`; a game that fires `LockBridge` needs its own client listener.
- Create every bridge clients use on the server during startup; a client that asks for a bridge before the server created it keeps an inert bridge.
- Game client code that requires `ReplicatedStorage.CmdrClient` itself must wait for its `Registered` attribute as `ClientCmdr` does: the first require on a client fixes which commands that client gets.
- A game pass bought in the experience now reaches the profile a few seconds later, once its ownership is confirmed, and "Thanks for your support!" shows then; game code that grants extras for a pass reads them from the profile instead of the prompt's result.
